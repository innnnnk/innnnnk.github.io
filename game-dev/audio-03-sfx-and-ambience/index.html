这份文档解决什么

00-conventions.md 定下了命名、域、总线与词汇纪律；配乐方向 定"听起来是什么"；Demo 补丁三 只给了 9 条概念。本文把三者落成一张可以直接照着采购、制作、接线的音效施工图：

  1. 事件目录是主干：80 条 AUD-* 事件，逐条给 ID、触发系统、资产规格、空间属性、并发/冷却、优先级、占位来源、验收方法。
  2. 区域环境音：六区 + 两条支线，逐区给底噪层构成、电平/滤波参数、AmbientSound Actor 布点规则。
  3. diegetic 声源：B 区营地口琴残句（来源不明、靠近即停）的实现参数。
  4. Boss 四阶段 / 战斗 / 交互 / 异常 / 转场 / 结束画面：补丁三 9 条 + 全部强制项逐一映射，覆盖度见 §9。

边界： 本文只写 SFX / 环境音 / diegetic / 语音呼喝。音乐 stem、强度曲线、主题配额归 02-music-implementation.md，本文只引用其常量；总线路由、SoundClass/Submix 树、导入代码规范归 01-architecture.md；响度与 ducking 的最终数值归 04-mixing-and-loudness.md。本文字段是按 00 总纲写的 DT_AudioEvent 行草案，01 定稿后以 01 的列结构为准调整。

前置事实： 音频零资产、零集成；UE 工程源码不在本工作区，所以本文是规格 + 触发契约，不宣称运行时已验证。所有触发点均落在 project-overview.md 已列出或 Demo 待办中已立项的类/系统上（DND_CombatManager、流程管理器、BP_EnconterTrigger、拾取物系统、文本交互弹窗、传送锚点、检查点系统等），不新造类名。

一、全局资产规格（本目录所有行默认遵守）

项 规定
源文件格式 WAV 48 kHz / 24 bit。禁止 96 kHz、禁止 32 bit float 交付
UE 内压缩 单次音效 < 1 s 用 ADPCM；其余 Vorbis Q0.65；循环资产必须 Looping 且首尾零交叉、10–20 ms 交叉淡化
声道 3D 点声源一律单声道；2D 界面/床/演出可立体声。禁止把立体声塞进 3D 点声源（会随相机旋转）
响度（临时值，04 定稿后覆盖） 单次世界音效 -18 LUFS，环境循环 -20 LUFS，UI -20 LUFS，VO -23 LUFS；true peak ≤ -1 dBTP
变体 P0 事件 3–4 变体，P1 事件 2–3 变体，P2 事件 1–2 变体；随机音高 ±50~±200 cents（见 §6）
时长上限 单次 ≤ 5 s（演出类 ≤ 8 s）；循环 30–60 s；超限须在本文登记例外

1.3 优先级定义

  • P0：缺了 Demo 观感直接断裂（战斗打击、Boss 四阶段、转场、A 区钩子）。
  • P1：Demo 可发布但明显"缺声音"，发布前必补。
  • P2：polish，可延期到新品节后补丁。

1.4 资产命名

SFX_<域>_<语义>_<变体号>，如 SFX_CBT_Hit_02；循环加 _Loop，如 AMB_Canyon_Detail_Loop；界面 UI_Backpack_Open；人声 VO_Companion_Grunt_Hit_01；MetaSounds MS_SFX_ImpactKit。事件 ID 与 GameplayTag 一一对应（AUD.CBT.Hit），ID 不复用，废弃标 Deprecated。工程内禁止 L3 词；矿石类资产一律 DeepMine_Ore，岩壁纹路一律 OldMine_Markings。

三、区域环境音设计

3.1 总体原则

一套基线 + 区域参数：补丁三 #1 要求的"森林底噪 A–F 全区循环"不录 8 套，而是一条 60 s 林地基线（AMB_Forest_Base_Loop）+ 每区的滤波/音量/细节层。这样既满足 #1，也把环境音文件数压到 9 条循环以内（与 Demo 的"一套资产 + 区域参数"思路一致）。

  • 基线层：2D 立体声，每区 1 个 AmbientSound，区域中心，不跟随，由 OnRegionChanged 交叉淡化（旧 0.5–1.0 s 出 / 新 0.8 s 入）。

3.3 AmbientSound Actor 布点规则

  1. 每区 1 个基线源：2D、无衰减、位于区域中心几何体附近，bAutoActivate=false，由流程管理器启停；禁止挂摄像机或玩家。
  2. 细节源固定：3D 源贴在岩壁/水体/树桩/孢子云上，不跟随玩家——跟随会产生"声音追着你跑"的假感。
  3. 跟随型仅 2 类：玩家脚步（挂 DND_CharacterBase）、孢子云体积（挂孢子云 Actor）。同伴脚步并入 VO 呼喝层，不单开跟随源。
  4. 每区 3D 常驻 ≤8 个，全图活跃 ≤32；超出 35 m 自动停播（衰减 Max Distance + 激活距离）。
  5. 相邻区之间留 10–15 m 无源缓冲（尤其 A/B、C/D），避免听到"隔壁区"。

  • 内存常驻循环：≤12 条（基线 1 + 区域 detail 7 + 嗡鸣 + 孢子云 + 冥想者 + 矿石，同时激活受区域限制）。

十一、性能与资产侧要求

  1. 单次 ≤5 s、演出 ≤8 s（SYS-007 唯一 8 s）；超限须在此登记。
  2. 采样率 48 kHz 统一；禁止 96 kHz、32 bit float、未压缩立体声大文件进构建。
  3. 3D 声源总量：全图同时发声 ≤32，每区常驻 ≤8；3D 单次超过 25–60 m（按衰减，04 §5.3）不播放。
  4. 2D 层不参与空间化：所有 UI、区域床、演出用 2D，避免相机旋转造成听觉漂移。
  5. 变体扩展：P0 3–4 变体、P1 2–3、P2 1–2；新增变体不改事件 ID、不改 DataTable 行结构。
  6. 循环资产唯一：同一循环不在两个 SoundClass 里重复导入；区域差异走参数/滤波，不复制文件。
  7. MetaSounds 优先：能用参数解决的不新增文件（§6 已把 9 个 MS 覆盖约 30 条事件的随机化）。
  8. 占位资产不得进发布构建：_Placeholder/ 目录打 exclude；发布前跑"占位引用检查"。
  9. 所有资产必须有 SoundClass + Submix Send + Concurrency；缺一项即视为未完成。
