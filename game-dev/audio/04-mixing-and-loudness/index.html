零、定位与不可违反的前提

本文档是音频模块电平与空间规则的唯一真源。总线树形状由 00-conventions §2 决定，本文档只填参数，不改结构。

本文档决定 本文档不决定
每条总线的静态增益、峰值上限、headroom 分配 总线树形状、SoundClass 命名（00 §1 §2）
全流程 / 单区 / 音乐床的响度目标与验收方法 音乐内容、stem 拆解、Boss 自动化（02）
ducking 的深度、时间、优先级、仲裁 SFX 事件目录与触发映射（03）
声像策略、衰减、遮挡、混响 send Submix 图、Control Bus、AudioModulation 类名（01）
母带交付规格、归一化、双验流程 资产前缀与目录树（00 §1.1 §1.2）

三条前提： ① 引擎内置、无中间件（00 前置事实 3）——标「由 01 实现」的，01 只能改实现、不能改行为；② 单人开发——任何"需要每个文件单独手工处理"的流程一律不采用（逐段响度归一化、逐句压缩都在此列）；③ 本文档所有 dB 值都是相对 Master 输出的操作电平，不是听感结论，听感由 §2 的 LUFS 目标负责，两者不可混用。

一句话总原则： 本作 80% 时间是 pp–mp（配乐文档 §1）。混音要保证"最安静的那 80% 也清晰可辨"，而不是"最响的那 3 分钟足够响"。所有数值都为这件事让路。

一、增益结构

三个测量点（全文默认 M2）： M1 = 交付 WAV 内部 sample peak（dBFS）；M2 = 各 Submix 输出点（dBFS）；M3 = SUB_Master 最终输出（dBTP，4× 过采样）。

1.1 总线增益表

总线 静态增益 峰值上限 @M2 内容响度目标 处理
SUB_Master 0.0 dB 工作峰 -4.0 dBFS / 硬顶 -1.0 dBTP 全 Demo -18 LUFS ±1.5 仅安全限幅器，GR 常态 0.0 dB
SC_Music -4.0 dB -9.0 dBFS（单段）/ -6.0 dBFS（交叉淡化期） 探索 -22 / 战斗 -19 / L3 -17 LUFS 无压缩；仅 ducking 增益
SC_Ambience -8.0 dB -14.0 dBFS（嗡鸣子层 -20.0 dBFS） -26 LUFS ±2 嗡鸣子层独立 send 与独立滑杆
SC_SFX -3.0 dB -8.0 dBFS（单次） 见 §2.4 总线上 1 个 peak limiter 兜底
SC_UI -6.0 dB -12.0 dBFS — 不参与任何 ducking（00 §2）
SC_VO -2.0 dB -8.0 dBFS — 最高 ducking 优先级
SC_Cinematic 0.0 dB -6.0 dBFS -18 LUFS ±1 接管时压其它总线，自身不推（00 §2）

1.2 headroom 推导（谁留了多少、为什么）

环节 预留量 留给谁
M1 交付峰值 -6.0 dBFS（不交 -0.1 dBFS） 5.9 dB ① 4 层 stem 满电平叠加的理论上限 +12 dB ② 无缝循环拼接 click 保护 ③ NG+/异常物的 pitch 偏移 DSP 过冲 1–3 dB ④ 运行期重采样
SC_Music 单段 -9.0 → 叠加上限 -6.0 dBFS 3.0 dB 战斗进出 1–2 s 内两段床重叠（00 §3 交叉淡化）；Boss 阶段三 1.0 s 静默后的全层同时回归——全 Demo 最陡的上升沿
SC_Ambience 比 Music 再低 5.0 dB 5.0 dB 嗡鸣 30–45 Hz 能量高度集中；室内混响的低频积累（§5.5）；它是唯一 24/7 不停的总线，长期声压贡献最大（§7.2）
Master 工作峰 -4.0 → 硬顶 -1.0 dBTP 3.0 dB 叠加、ducking release 回弹、转场交叉

叠加验算（按功率和，互不相关信号）：音乐交叉期 -6.0 + 环境 -14.0 + SFX -8.0 + VO -8.0 + UI -12.0 ≈ -1.7 dBFS，贴住 -1.0 dBTP 硬顶。这正是硬顶必须存在的理由——不是"我们不会超"，而是"我们算过最坏情况就在天花板下面 0.7 dB"。不允许同时打满的原则由 concurrency（CON_*）与 §4 的仲裁共同保证。

1.3 三条写死规则

  • R1 fader 只做平衡，不做响度校准。响度校准只能改交付资产，否则 §2 的目标会在运行期漂移。
  • R2 除 §3.2 允许的 3 个限幅器外，任何 Submix/SoundClass 上不得挂压缩器、多段、饱和。禁止"压缩 + makeup gain"替代 fader。
  • R3 任何 +dB 的增益必须写进 §1.1 并重算 §1.2；未入表的正增益视为 defect。

二、响度目标与测量

2.1 平台现实（诚实版）

  • Steamworks 提交审核不检查 LUFS，公开的提交清单里没有响度项；PC 平台也没有主机 TRC/XR 式的响度条款。没有任何外部力量会拦住一个 -10 LUFS 的游戏——这既是自由也是风险（“声音太小/太吵"是少数无法靠补丁解释的差评来源）。
  • PC 播放链路玩家可控：系统音量 0–100%、耳机与笔记本扬声器差异可达 30 dB 以上、Windows 音量合成器、部分玩家开着系统"响度均衡”（自带压缩）。我们不能假设播放电平。
  • 结论：不追求"响"，追求动态曲线不被播放环境抹平——这条直接推出 §2.5 的第一条"不做"。若未来上主机/移动，需另立响度条款，本文档不覆盖。

2.2 我执行的目标值（验收依据，不是建议）

项 目标 容差 / 上限 测量窗 测量点

单区 integrated A/B/D/F -24 ~ -21；C -19 ~ -17；E -17 ~ -15 LUFS 区际差 ≤ 3 LU 该区完整时长 M3
Short-term 上限 ≤ -11 LUFS 任何 3 s 窗 3 s 滑动 M3

2.3 测量方法（含零付费工具链）

(a) 离线——唯一有权威性的方法。

  1. 抓取：OBS 录桌面音频（WASAPI output capture，48 kHz / 24-bit / 立体声 WAV）。Windows 主音量 100%，游戏内 Master 0 dB，关闭"响度均衡"。
  2. 测量：Youlean Loudness Meter 2 Free（VST3/AAX，免费，可读 integrated / short-term / momentary / true peak；记录与报告导出是付费功能 → 手工抄表）；REAPER 自带 LUFS 电平表与渲染归一化（支持 LUFS-I / LUFS-S / true peak，非免费：60 天评估后约 $60，精度最高）；Audacity 的 Loudness Normalization 只读 integrated LUFS 且不测 true peak，故只当归一化工具、不当验收工具；零预算宿主可用 Tracktion Waveform Free 挂 Youlean。
  3. 不做的事：不把未发布素材上传任何在线 LUFS 分析网站（版权 + 版本污染）。

(b) UE 侧只能近似——必须写清楚，否则验收会变成玄学。

  • UE 5.6 引擎没有 BS.1770 LUFS 表，也不测 true peak（需 4× 过采样，引擎不提供）。可用只有 Master / Submix 的 peak、RMS 电平表（dBFS）→ 只能验 §1.1 的 M2 上限，不能验 §2.2 的 LUFS 目标。
  • AudioSynesthesia 的 LoudnessNRT / LoudnessAnalyzer 返回归一化感知响度、不是 LUFS，只能做 A/B 段落相对比对（误差 ±2 dB 量级）。
  • 因此：运行时不验收 LUFS，只验三件事——① 各总线 peak 不超 §1.1；② 安全限幅器 GR 常态 0.0 dB；③ ducking 深度实测与 §4.2 表误差 ≤ ±0.5 dB。

(c) 监听校准的现实约束： 没有 SPL 计就无法做绝对监听电平校准。替代：固定一副封闭耳机 + 一台笔记本扬声器 + 固定系统音量 40% 并记录，全部 A/B 在此基准下做；参考片段 = A 区底床前 10 s，作为全项目的电平地标。

2.4 单次 SFX 的事件级规范

事件时长 指标 上限
< 200 ms（底座阴影脉冲、铭牌拾取） sample peak @M3 ≤ -8.0 dBFS
200 ms – 3 s（孢子释放、菌丝出体） Momentary（400 ms） ≤ -16 LUFS
> 3 s（嗡鸣循环、风） Short-term（3 s） 嗡鸣 ≤ -20 LUFS；风 ≤ -24 LUFS
任意 true peak @M3（solo 播放） ≤ -6.0 dBTP
任意 对 Master short-term 的抬升 ≤ 3 LU

理由：BS.1770 的门限会把 < 400 ms 的内容基本剔除，短事件用 LUFS 无意义，只能用峰值；长事件才用响度。“单次 SFX 的 dBTP 上限"与"音乐床 LUFS"是两套工具，不要混用。

2.5 不做什么

  • 不做运行期响度归一化 / loudness matching（例如把所有音乐段拉到同一 LUFS）。那会直接抹平配乐文档 §4 的情绪曲线：F 区结尾必须是全 Demo 最干净、“终于说出口"的一段，Boss 阶段三的 1.0 s 必须是真静。这是本文档最重要的一条"不做”。
  • 不按峰值归一化音乐（长音多的段落会变小声，与 pp–mp 设计相反）；不做默认开启的"总音量自动压缩”（作为可访问性选项存在，见 §7.3，默认关）。

三、动态范围策略

3.1 三句话结论

  1. 不上总线压缩：Master、Music、Ambience、Cinematic 全部不加压缩器/多段/磁带饱和。
  2. 只放 3 个安全限幅器：Master（-1.0 dBTP）、SC_SFX（-6.0 dBTP 兜底多实例叠加），以及 MetaSounds 内部的循环接缝保护（不算总线处理）。
  3. 动态由编曲与编排提供，不由混音提供。f 是稀缺资源（配乐文档 §1），压缩等于把稀缺变成常态，与本作声音身份直接冲突。

3.2 限幅器参数

挂点 阈值 比例 Lookahead Release 允许 GR
SUB_Master -1.0 dBTP ∞ 5 ms 50–100 ms 常态 0.0 dB；允许瞬时 ≤1.0 dB 且累计占时 <0.5%
SC_SFX -6.0 dBTP ∞ 3 ms 40–80 ms 常态 0.0 dB；>4 实例同时才允许 ≤3.0 dB
SC_Music 不挂 — — — —

区间理由：lookahead 3–5 ms 是"抓得住瞬态又不会被听成前置"的最小窗；release 40–100 ms 保证鼓刷（本作唯一打击乐）不被"抽气"；阈值贴 M3 上限而不是工作峰值，保证它只在 defect 时工作。

3.3 “不做"的取舍

不做 换到的好处 付出的代价
总线压缩 ① 少一个会随 30 s 嗡鸣循环相位起伏的 pumping 源 ② ducking 深度可预测（压缩后测得的 -3 dB 会漂移，验收变灰）③ 17 dB 峰均比完整保留 小音量环境下 pp 段可能听不清 → 交给 §7.3 的可访问性选项而不是全局压缩；“响度不够现代”→ 接受，本作对标 Disco Elysium / Outer Wilds，不是 3A trailer
多段压缩 省掉 40–60 Hz 与 2–4 kHz 互相调制的调试时间（单人开发的成本就在这里） 对白清晰度只能靠 §4 ducking 与 §5 声像解决
母带饱和 / 磁带 爵士三重奏谐波已足够；加饱和会让 double bass 与钢琴低音糊 无

3.4 “忽大忽小"归因表（本文档存在的主要理由）

玩家会说 真实原因 在哪一层修 不允许的修法
“进 B 区突然小声了” 区域底床 LUFS 没对齐 §2.2 单区目标 + §8.4 交付归一化 给 Ambience 加压缩
“弹窗一开音乐像抽了口气” ducking attack/release 太快 §4.2 D01（150 ms / 250 ms） 用侧链压缩
“战斗结束音乐变小声” 交叉淡化 1–2 s 内两段床叠加被限幅 §1.2 的 3 dB 交叉预算 降战斗曲响度
“笔记本上什么都听不见” 笔记本扬声器 100 Hz 以下几乎无重放，低频嗡鸣全丢 §7.5 设备降级 + §8.5 笔记本必测 抬总音量
“Boss 战好吵” 单次 SFX 峰值叠加 + 音乐同时满 §2.4 事件上限 + §4 优先级 全局压 Master（会毁 F 区结尾）
“结尾那段为什么那么轻” 那是设计（8–16 s 干净段，00 §3） 不改 “修"它

3.5 兜底（只有 §3.4 全部处理完仍被投诉才允许）

加 1 个慢速总线软化：ratio 1.5:1–2.0:1、阈值取到 GR 常态 0.0–0.5 dB、attack 250 ms、release 500 ms，只挂 SUB_Master，且必须登记进 §9.3。禁止：多段、并联鼓总线式处理、任何 <100 ms attack 的总线压缩。

DuckSource { busMask, depthDb, attackMs, holdMs, releaseMs, priority, id }

onBegin(src):
  for bus in src.busMask:
    set[bus].push(src)
    t = maxDepth(set[bus])                 // R1 不累加
    if t != current[bus]: ramp(bus.gain, t, src.attackMs)
onEnd(src):
  set[bus].remove(src)
  if set[bus].empty: ramp(bus.gain, 0, src.releaseMs)        // R3 从实测值起算
  else:              ramp(bus.gain, maxDepth(set[bus]), 60)  // 60 ms 短平滑，避免台阶
onCritical(src):                            // P4 / P4c
  set[bus].clear()                          // R4
  ramp(bus.gain, src.depthDb, src.attackMs)
  on end: ramp(bus.gain, 0, src.releaseMs)  // 不恢复旧栈

所有 ramp 使用"当前实测值 → 目标值"的指数或 S 形曲线；被新事件打断时从实测值重新起算，不重头。

4.5 验收点

五、空间化

5.1 结论（先给答案）

维度 用哪个坐标系 理由
声像（azimuth / pan） 相机相对（相对 Audio Listener = 相机） 俯视固定视角下，玩家的空间认知 = 屏幕平面。画面左边有敌人，声音必须在左边。世界坐标 pan 在相机转向或传送后会与画面相反——这是本作最容易发生、也最难被原谅的错误
距离衰减 世界坐标（相机到声源）；Demo 相机不做 zoom，两者近似等价，直接用引擎默认 ATT 若以后加相机 zoom，必须改用 Pawn 到声源的距离驱动 attenuation 参数
遮挡 世界坐标（体积） 遮挡是物理事实，与相机无关
混响 send 世界坐标（区域 / 体积） 混响是空间属性，不是听觉方位
垂直升角 / HRTF 不使用 2.5D 纸片人是正面朝向镜头的投影，高度差信息为零；开 HRTF/elevation 只会让声音"从屏幕上方来”，而那里什么都没有

判定依据一句话： 2.5D 纸片人世界里的"真实空间"在美术层面是投影，玩家的空间推理完全依赖屏幕；因此方位必须跟屏幕走，物理属性（距离、遮挡、混响）必须跟世界走。

5.2 2.5D 纸片人的三条修正

# 问题 修正
1 纸片人永远正面朝镜头，玩家读不出"它面朝哪"，缺少"声音来自它正前方"的视觉锚点 角色的发声事件（攻击、受击、呼喝）允许完整 pan；状态音（idle 呼吸、菌丝蔓延）pan 压缩到 ±30%，避免"角落里有人在呼吸"的过度定位暗示
2 Sprite 大小不随距离严格缩放（billboard），视觉距离不可靠 衰减必须做成三档可辨（近 0–8 m / 中 8–20 m / 远 20–45 m），不做连续平滑；见 §5.3

6.4 硬约束（五条，违反即 defect）

  1. 旧混响 send 淡出时长 = max(0.35 s, RT60_old / 4)，且 ≤ 黑屏时长 + 0.2 s。本作 RT60 最大 2.4 s（E 区），/4 = 0.6 s ≤ 0.5+0.2 ✓。若未来 RT60 超过 3.0 s，先缩短黑屏前淡出，不许加长黑屏。
  2. 禁止在黑屏第一帧瞬切 reverb——会产生 click 与尾巴断口。混响不依赖房间体积自动计算（Demo 无全覆盖音频体积）→ 8 个手工 preset。
  3. 黑屏期间禁止 UI 音与 SFX（转场 whoosh 除外）：血条、拾取、铭牌计数音全部静音。
  4. 音乐在区域转场不做切除（只做 whoosh 掩盖）。理由：转场把音乐也切了会破坏配乐文档 §3 的连续床设计。
  5. 失败兜底：流程管理器若 2.0 s 内没收到"黑屏结束"，音频侧强制把 reverb 设为"当前区域"预设（幂等），环境音拉到 -30 dB 待命、1.0 s 后恢复。宁可"空间感错一下"，也不能"混响停在错误房间"直到下次转场。

7.2 低频嗡鸣：风险与五条缓解（本文档重点）

风险事实： 40–60 Hz（本作实际基频 36.7 Hz，见 §10 第 1 条）是"体感频率"而非"听觉频率"。等响曲线在低声压时对 40–60 Hz 要求显著更高声压才等响 → 玩家为了"听见"会把系统音量推高 → 实际低频暴露量远高于读数。LUFS 的 K 加权对 40–60 Hz 只衰减约 2–4 dB（RLB 高通转折 ≈38 Hz，量级判断、不作验收依据），所以 LUFS 表不会替我们报警。长时间低频暴露的已知风险是听觉疲劳、头痛、耳鸣；游戏行业没有强制上限，这个上限我们自己定。

# 措施 数值
1 时长上限 D+E 区连续低频暴露 连续 ≤ 240 s；达 240 s 嗡鸣自动淡出到 -18 dB 并保持 ≥ 45 s 后恢复；累计 ≥ 600 s 再降 -6 dB 并给一次性提示
2 音量上限 嗡鸣子层在 M3 的稳态 30–60 Hz 频带 RMS ≤ -30 dBFS；嗡鸣对 Master 的贡献 ≤ 3 LU（去掉嗡鸣后 integrated 变化 ≤ 3 LU，可测）
3 独立滑杆 §7.1 最后一行 -60 ~ 0 dB，默认 0 dB；首次进入 D 区一次性提示，可勾"不再提示"
4 频段避让 非嗡鸣内容的 30–80 Hz 挖空 Music：40 Hz 以下高通 + 50 Hz 起 -6 dB shelf；SFX：除非设计明确要求不写 40 Hz 以下；Ambience 非嗡鸣层：80 Hz 高通
5 混响隔离 reverb send 高通 120 Hz（§5.5） 硬要求，防止室内低频积累

另加一条：首次启动一次性安全提示（“本作包含持续低频与突发音效”），可在设置关闭。【新增】

7.3 突发音保护 / 字幕 / 设备降级

  • 突发音：单次事件 peak ≤ -8.0 dBFS、true peak ≤ -6.0 dBTP（§2.4）；同一 200 ms 窗内 > -20 dBFS 的瞬态事件 ≤ 3 次（CON_* 限流，超额按"优先级 + 空间距离"丢弃最远实例）；可访问性开关「动态范围压缩」默认关，开启后 Master 后级 2.0:1–3.0:1、attack 10 ms、release 200 ms，把 12–20 LU 的 LRA 压到 6–8 LU，选项文案必须明说"会削弱强弱对比"。
  • 字幕：Demo 无台词配音（03 §7.1、00 §8.1 #27），非语义呼喝无需字幕；所有叙事信息本就以文本呈现，语音字幕系统为正式版预留（屏幕底部、黑底 70% 不透明度、对比度 ≥ 4.5:1、字号 100–200% 可调、与音频延迟 ≤ 100 ms、左右方向用「（左侧）」文字标注、挂在 SC_UI 不受 ducking 影响）。关键叙事 SFX（菌丝出体、孢子释放、铭牌拾取）在"字幕/提示"开关下可给拟声描述，默认关——会破坏冰山原则。
  • 设备降级：笔记本扬声器 100 Hz 以下几乎没有重放 → 嗡鸣（36.7 Hz）在笔记本上完全消失。因此 ① 不允许任何叙事信息只存在于低频（“嗡鸣消失 = 世界安静"已由 F 区的风与手写体文本承担）；② 笔记本上验的是”没有嗡鸣时氛围是否仍然成立"，不是"嗡鸣是否听得见"；③ 单声道折叠后 Master peak 可能 +3 ~ +6 dB（相关信号）→ 不得超 -1.0 dBTP，必须实测；④ 设置页建议提示关闭 Windows"响度均衡"（它会与本作动态曲线打架）。

采样率 / 位深 tempo-locked 音乐循环：44.1 kHz / 24-bit（63 BPM 整数采样，00 §8.1 #20）；单次演出与 one-shot：48 kHz / 24-bit；工程内 32-bit float
声道 音乐床 / stem 一律立体声 2.0；不交 5.1 / Atmos（本作不用环绕）
峰值 -6.0 dBFS（不交 -3 dBFS，不交 -0.1 dBFS）
响度 交付即按 integrated LUFS 归一化：探索床 -22 ±1、战斗床 -19 ±1、结尾主题 -17 ±1（与 §2.2 一致）
循环 首尾零交叉、长度按小节整数；不要自带淡入淡出；loop 点在清单标注
原始版本 归一化前的原始混音（峰值留 12 dB）随包交付，便于重混

“是否带 -3 dB 余量"的答案是不带，带 -6 dB：① 4 层 stem 满电平叠加理论上限 +12 dB；② 无缝循环拼接的 click 保护；③ NG+ 的 pitch 收敛与异常物偏移（+5~+15%）滤波过冲 1–3 dB；④ 导入 / 重采样。任何一条在 -3 dB 下都会贴顶。

8.3 命名与清单

严格用 00 §1.1 前缀；文件后缀 _Lp（循环）/_OS（单次），如 AMB_Forest_Base_Lp.wav、SFX_CBT_Hit_OS.wav。清单每行 7 列：文件名 / 时长(s) / 循环(是/否) / 声道 / 峰值(dBFS) / integrated(LUFS) / 交付日期。交付包目录与 00 §1.2 的 Content 树同构（作者直接按目标目录放，不建 Audio_New 之类临时目录）。

8.4 归一化流程（零付费工具）

① 批量测：Youlean Free 或 REAPER 逐个测 integrated LUFS + true peak，抄进清单；② 归一化：Audacity → Loudness Normalization（perceived loudness / LUFS）设目标值，或用 REAPER 渲染窗口的 LUFS-I 归一化 + true peak 限制；③ 复查：归一化后重测峰值，确认 ≤ -6.0 dBFS、TP ≤ -6.0 dBTP；④ 抽检 10%：用第二套工具复测，差异 > 1.0 LU 则全批重测（防工具链系统性偏差）。

8.5 双验流程（耳机 + 笔记本扬声器）

项 内容

基线 系统音量 40%、Windows 主音量 100%、关闭"响度均衡”、游戏内 Master 0 dB

9.2 责任线（谁改得动什么）

  • 作曲：只按 §8 交付。不得在资产上预压、预限幅、预加总；觉得某段不够响 → 走 §9.3，不许自己抬 3 dB。
  • SFX：只负责事件设计与交付；单次音效的响度由 §2.4 决定，03 不得在资产上做 compress-to-target。
  • 架构：实现 §1、§4、§5、§6 的结构与参数；不得引入第二套电平管理（例如"顺手"在 Master 前挂个压缩器）——这是最容易发生、且会让 §2 全部验收失效的一件事。
  • 混音（本文档）：所有 dB 值的唯一真源。任何文档里的 dB 若与本文档冲突，以本文档为准，并标 ⚠️。

9.3 变更流程

“我想更响 / 更轻"的请求必须写成一句：场景 + 当前实测值 + 期望值 + 理由 → 由混音改 §1 / §2 表 → 重跑 §8.5 双验 → 记进 defect 表。不走这个流程的 dB 改动一律视为 defect。

十、待城主确认（6 条）

# 事项 本文档的暂定处理 影响面
1 嗡鸣基频：配乐文档 §5 定为 D1 ≈ 36.7 Hz，补丁三 #2 写的是"40–60 Hz”（36.7 Hz 不在该区间内） 按 36.7 Hz 设计；§7.2 的频段避让按 30–45 Hz 窗口做 低频疲劳策略的全部数值
2 pitch 偏移方向：00 §3 与补丁三 #3 是 +5~+15%（上行）；entropy-time-ideas 的听觉设计是"密集区整体偏低 5–15%"（下行） 暂按上行 +5~+15%（00 为唯一真源）；但要求嗡鸣最终基频不越出 30–45 Hz——下行 15% 会到 31.2 Hz，接近次声且笔记本完全无法重放 空间化与低频策略都依赖这个方向
