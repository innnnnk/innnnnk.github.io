这份文档的作用

音频模块此前只有两份方向性文字：

  • 配乐方向与声音状态设计 —— 决定"听起来是什么"（声音身份、单主题贯穿、交互音乐分层、六区情绪曲线、Boss 四阶段音乐）
  • Demo 深潜版 补丁三 —— 决定"需要哪些音效"（9 条 SFX 概念清单）

两者都是设计意图，不是施工图：没有资产命名、没有总线、没有事件 ID、没有参数名、没有接口、没有排期。

本目录下的文档集把它们落成可施工的模块。本文件是总纲：后面 4 份文档的所有命名、常量、接口都以本文件为准；发现冲突时以本文件为准并标注"待城主确认"。

前置事实（必须知道）：

  1. 音频目前零代码、零资产、零集成。
  2. 本工作区只有设计文档，UE 工程源码不在这里。因此交付物是「规格 + 可直接粘贴的代码草案」，不编译、不验证运行时行为。
  3. 音频中间件选定为引擎内置（MetaSounds / Submix / AudioModulation），不引入 Wwise / FMOD。理由：单人开发、Demo 规模、无中间件集成预算。
  4. 所有工程内命名受词汇敏感度矩阵约束（见下文「工程代号纪律」）。

五、与其他模块的接口契约

音频模块不主动轮询任何状态，全部由现有系统广播事件。以下接口是本模块对其他模块的全部要求，多一条都不该加。

广播方 事件（建议签名） 音频侧行为
流程管理器 OnRegionChanged(FName RegionId) 切 AMB 底噪、切混响 Submix、重设 MusicIntensity 基线
流程管理器 SetMusicIntensity(int32 0-4) 驱动 MS_ExploreBed / MS_CombatBed 的强度输入
传送锚点 OnTeleportBegin / OnTeleportComplete 音频先行偏移（0.5~1.0s）、黑屏期切环境音、出口淡入
CombatManager OnCombatBegin / OnCombatEnd 横向切换到战斗段（小节边界量化）
CombatManager OnTurnStarted(AActor* Unit) 回合提示音、树桩注视彩蛋的可听化（可选）
文本弹窗 OnPopupOpen / OnPopupClose 底床 -3dB ducking
同伴状态机 OnCompanionStateChanged(Ally/Infected/Released/Dead) D 区律动"慢半拍"、释放演出的静默与单音动机、死亡分支的情绪降级
GAS GE_SporeAwareness 授予 极低频异常文本/听觉层的解锁（种子，可只留接口不实现）
拾取物系统 OnPickup(ItemId) 铭牌拾取音、晶核脉动（开背包时）
演出/流程 OnAnomalyTriggered(AnomalyId) 叠加 Unease 层 / pitch 偏移，不切歌

反向依赖原则： 音频侧不得让战斗/流程逻辑依赖音频返回值。所有播放接口返回 void。

六、写作规范（本目录所有文档）

  1. 每个资产/事件行必须给全：ID / 用途 / 时长 / 循环 / 声道 / 格式 / 优先级 / 触发点 / 验收方法。
  2. 数值给区间和单位，禁止写"合适的音量"“适当衰减”。
  3. 结论必须可追溯：新结论标注来源（哪份文档哪一节），凭空新增的设计标注 【新增】。
  4. 与既有文档冲突时：不擅自改既有文档，在本目录内标注 ⚠️ 待城主确认：与 X 文档 Y 处冲突。
  5. 中文、Markdown、front-matter 与 game-dev/ 下其他文档一致（title / description / date / slug / draft / tags）。
  6. 单份文档目标 300~600 行：够施工，不写成长篇小说。

七、术语表

术语 含义
Stem 同一段落的分轨（底床/律动/旋律/不安），可独立开关
Vertical Remixing 纵向分层：同一时间轴加减 stem
Horizontal Re-sequencing 横向切换：在段落边界换曲
ducking 一侧信号压低另一侧（如弹窗时压低底床）
sting 短促的音乐提示音（如"释放"瞬间）
L1/L2/L3 主题出现层级：碎片不可指认 / 变形 / 完整可哼唱
diegetic 世界观内声源（角色也能听见，如营地口琴）
Mob / Ambient bed 环境底噪循环层
