1.2 为什么不用 Wwise / FMOD

  1. 成本倒挂：单人开发，中间件接入（SDK + 事件表 + 打包链 + 版本绑定）约 36 周；Demo 音频总量 = 补丁三 9 条 SFX + 配乐 §6 的 7 条音乐 + 2030 条环境/交互音效。
  2. 能力足够：配乐要求的纵向分层、横向小节切换、参数化（MusicIntensity / swing 抖动 / pitch 偏移）MetaSounds + Quartz + ControlBus 全覆盖（配乐 §3、§6）。
  3. 少一套授权与打包产物：无 .bnk/.bank、无中间件运行时 DLL，包体与崩溃面更小；引擎内置方案在 5.6→后续版本迁移成本最低。

1.3 明确的不可行点（认账）

# 不可行 / 缺失 应对
1 没有 Event 层级 + State/Switch 容器 自建 GameplayTag 键 + DT_AudioEvent 参数表（§三、§四）
2 没有随机容器/权重/交叉淡化的音效播放器 Subsystem 内实现随机区间 + 池化 + 抢占；多层材质矩阵不做

2.3 职责边界，以及为什么这样切

切割轴：生命周期（GameInstance / World）、状态唯一写者、依赖方向。

类 只做 绝不做 不这么切会怎样
Subsystem “请求→发声"机械路径：查行、闸门、加载、池、组件属性、转场时序 不判音乐语义；不持玩法强引用（只用弱引用取位置） 音乐状态机 tick 污染每帧播放热路径
MusicDirector 音乐语义状态机：强度目标、2/4 小节量化、stem 增益、Boss 四阶段、静默段、配额、CB_Hum* 唯一写者 不直接播一次性 SFX；不管加载（走 Subsystem helper） 音乐连续性无法跨关卡；GameInstance 级对象写世界级委托必悬垂
Router 把已有系统委托翻译成上面两者调用；管绑定生命周期 不持音频状态；不做决策（只做映射） 委托句柄属于世界，写进 GameInstance 级对象必然悬垂
BP Library / PoolHost 静态转发；组件容器与空闲标记 不含分支逻辑；不选资产不做闸门 玩法模块被迫 include Subsystem 头；组件无法注册进世界

为什么不是两个类（Subsystem 全包）： 音乐状态要能在关卡切换/无世界时冻结不丢值，SFX 服务要能在世界重建后立刻可用——生命周期语义不同；且单写者规则（每个 CB_* 一个写者，Debug 断言）需要音乐语义与播放机械分离才能静态检查。 为什么不再拆更多类： 区域环境切换 = 1 条 voice 淡出/淡入 + 时间戳 + 一条 Submix 斜坡（<60 行）；资产注册表 = 一张 TMap。给它们独立类就是空壳。判据：只有拥有独立生命周期或独立状态写者身份时，才允许单独成类。

3.2 为什么是「Tag 作键 + DataTable 作参数表」

  • 纯 Tag：带不动资产与数值，最终退化成 switch(Tag) 硬编码——每加一个音效改一次 C++，单人项目最贵的成本。
  • 纯 DataTable（FName 键）：失去层级与命名空间约束，拼写错误只能运行时发现，且无法与 GAS / GameplayCue 的 Tag 世界互操作。
  • 双键：Tag 负责"谁触发什么”（编辑器可校验、可被任意系统广播、可层级查询），表负责"响了会怎样"（资产/音量/冷却/优先级，改表不重编译）；RowName 承担稳定事件 ID。
  • 索引：首世界构建 TMap<FGameplayTag, FName>，O(1)；查不到 → LogDNDAudio Warning + 计数 + 静默返回，不 crash 不打断战斗。

六、导入规范

采样率按总纲 §8.1 #20：tempo-locked 音乐循环 44.1 kHz（63 BPM 整数采样，02 §3.4），其余全部 48 kHz；源 24-bit WAV，导入前清元数据、按 03 留授权凭证。

类别 UE 内格式 压缩 声道 循环 虚拟化 内存/文件
短 SFX（<2 s） SoundWave PCM 16-bit 3D 单 / 2D 立体声 否 Restart，不流式 ≤1 MB
中 SFX（2–8 s） SoundWave ADPCM 3D 单声道 视用途 同上 ≤2 MB
环境循环（30–60 s） SoundWave / MS Wave Player Vorbis q0.50–0.70 底噪立体声、点声源单声道 是，采样点精确 PlayWhenSilent 全环境 ≤8 MB
音乐 stem（60–120 s） MS_* 内 Wave Player Vorbis q0.70–0.85 或 Bink 立体声 是，同组等长同起点；44.1 kHz 交付（02 §3.4） 不虚拟化/不流式（保相位） 全音乐 ≤24 MB
VO（0.3–3 s） SoundWave ADPCM 单声道 3D 否 播放中不虚拟化 ≤512 KB
  1. 3D 一律单声道——立体声做点声源会让声像与 LPF 退化；只有 2D 层用立体声。
  2. 循环点以采样计（48 kHz 下 1 sample ≈ 20.83 µs），接缝靠近零交叉；验收 = 播 10 次无 click、频响无 >3 dB 塌陷；MetaSound 循环优先。
  3. stem 同长同起点：一区音乐用一张 MS_* 图内多 Wave Player，不用 4 个 AudioComponent——相位对齐前提，也省 voice。
  4. 导入口峰值 ≤ −6 dBFS；响度归一化目标走 04（占位：单次音效 −20~−18 LUFS short-term，音乐床 −18~−16 LUFS integrated）。
  5. 循环资产 bLooping + SoundClass PlayWhenSilent；一次性 3D 用 Restart，避免"远处播过、走近重播"。
  6. 命名只允许 00-conventions §1.1 前缀，术语只用 §四 代号（Motif-X / Bed / Pulse / Unease / DeepMine_Ore / MineGlyph），禁词表零出现；行名、参数名、注释、日志同样受约束。

7.6 跨总线嗡鸣控制（与 02 的核心接口）

问题： 00-conventions §2 规定嗡鸣层物理上属于 SC_Ambience（要跟环境音一起淡入淡出），但它的基频与音量曲线由音乐导演控制——它是主题基频低 2 个八度，F 区结尾"嗡鸣淡出 → 主题响起"要求两者锁定同一基频。

方案：播放权归环境，调制权归音乐，通过 ControlBus 解耦。

  1. 资产：MS_AmbHum_Low（MetaSound Source，输出路由 SC_Ambience；波形 AMB_Hum_Low_Loop 放 Content/Audio/Ambience/），图内 3 个输入：BaseFreqHz（默认 36.7 Hz = 主题首音 D3 低 2 个八度，00-conventions §3）、PitchRatio（绑 CB_HumPitch）、Gain（绑 CB_HumGain）。
  2. 播放权：该 voice 与区域底噪一起管理（同一次淡入淡出、同一条 CON_Ambience_Region）；音乐导演不持有 voice。
  3. 调制权：音乐导演是 CB_HumGain / CB_HumPitch 唯一写者，Subsystem 在 Debug 断言"写者 == MusicDirector"；其他系统只能经 NotifyAnomalyProximity(0–1) 上报接近度，由导演合成 PitchRatio = clamp(HumBaseRatio × (1 + Lerp(0.05, 0.15, proximity)), 0.95, 1.18)（+5%~+15% 来自补丁三 #3）。
  4. 为什么必须这么切（三个反例）：① 音乐导演直接播 hum → 绕过 SC_Ambience 区域增益包络，F 区转场拉起环境时 hum 被"复活"，8~16 s 干净段被破坏；② 环境系统拥有 pitch → Boss 阶段三"全部音乐抽空 1.0 s"时导演无法让 hum 一起静音；③ 双方都能写 → 双写冲突（异常物 + Boss 阶段同时生效时无人裁决上限）。
  5. 边界情况（需状态断言）：抑制锁——NotifyRegionChanged(F_Path) 后导演置 bHumSuppressed=true 并写 CB_HumGain=0，区域底噪重拉时不得重置该总线（写者是导演，天然满足），EndSilenceSection 后才解锁写 1.0；转场瞬间——HandleRegionTransitionBegin 先 SetHumAnomalyOffset(0)，不把旧区偏移带进新区；黑屏窗口——CB_HumGain 在 0.5–1.0 s 内斜坡到 0（音频先行），新区域 0.8 s 淡入，F 区整段演出保持 0。
  6. 验收：D 区接近纹路，0–5 m 内 CB_HumPitch 单调升至 +15%±1%，离开 3 s 内回落；F 区结尾 hum 8–16 s 内 ≤−60 dBFS 且不被区域转场拉起。
